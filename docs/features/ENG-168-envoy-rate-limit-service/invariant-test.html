INV-1 · already-proven

For any domain a peer holds at most one entry, the highest (version, origin) received; merge is the only write path; tombstones go through it.

Source blueprint I1; ADR-0004 · Resources envoyPolicyStore map · Defenses store mutex, atomic snapshot pointer

Purpose Every peer converges on the same winner; deletes are never resurrected.

  • integrity — peer holds a lower (version,origin) entry. KEEP: mutex serializes writes but cannot pick the winner; ListPolicies exposes the stored entry
  • ordering — older apply resurrects a tombstone. KEEP: ordering rule lives in merge, not the mutex
  • other — concurrent writes outside the lock. DISCARD: only -race sees it; suite already runs under -race

Test envoy/envoy_test.go: TestStalePeerUpdateIsDiscarded, TestEqualVersionsBreakTiesByOrigin, TestDeleteSurvivesReplayOfOlderApply

Mutation mergeLocked no longer discards entries that do not outrank the stored pair → red; reverted → green.

Source blueprint I2; principle 1 · Resources adapter request batch · Defenses none

Purpose No limit value originates in gubernator configuration.

  • integrity — no-override descriptor counted against a server-side number. KEEP: current_limit echoes only descriptor overrides; a built request would populate it

INV-3 · already-proven

The same multiset of entries yields the same name and unique_key regardless of entry order.

Source blueprint I3 · Resources derived name/unique_key · Defenses none

Purpose Two Envoys sending the same entries share one bucket.

  • integrity — reordered entries land in a second bucket with full quota. KEEP: limit_remaining on the second call exposes the shared bucket
  • ordering — duplicate keys reordered between calls. DISCARD: documented: stable sort keeps duplicate keys in arrival order; two arrival orders are two buckets by design

Test envoy/envoy_test.go: TestEntryOrderDoesNotChangeBucket

Mutation sort removed from identity() → red; reverted → green.

INV-4 · already-proven

Source blueprint I4; ADR-0004 · Resources envoyPolicyStore · Defenses store mutex

  • integrity — same-millisecond or clock-regressed apply gets an equal/lower version and is discarded by merge. KEEP: Applied[].Version is returned to the caller
  • ordering — peers disagree on the winner for equal versions. KEEP: ListPolicies per peer

INV-5 · mutation-verified

Never report a descriptor OK that gubernator did not evaluate: any per-item RateLimitResp.Error or transport failure fails the whole call with Internal.

Source blueprint Behavioral Constraints; principle 4 · Resources ShouldRateLimit response · Defenses none

Purpose Envoy's failure_mode_deny decides; nothing fails open silently.

  • integrity — an unevaluated descriptor is reported OK and Envoy admits uncounted traffic. KEEP: an empty entry value yields an empty unique_key which gubernator rejects per item; the call's gRPC code is observable
  • other — transport failure to the owning peer swallowed. DISCARD: same code path: forwarding failures surface as RateLimitResp.Error strings, covered by the per-item test

Test envoy/envoy_test.go: TestPerItemErrorFailsTheWholeCall: codes.Internal, message names unique_key, requests_total{code=Internal} incremented

Mutation adapter skips the rl.Error check → red; reverted → green.

INV-6 · needs-observability

ShouldRateLimit never blocks on policy propagation; policy lookup reads an in-memory snapshot and never touches the network.

Source blueprint Behavioral Constraints; principle 5 · Resources policy snapshot · Defenses atomic snapshot pointer

Purpose Envoy traffic is not held hostage to peer reachability.

  • liveness — ShouldRateLimit hangs while peers are unreachable. DISCARD: rate-limit forwarding to an owning peer legitimately uses the network on the same call, so latency cannot be attributed to policy lookup from the surface
  • timeliness — policy lookup latency grows with peer reachability. DISCARD: same masking by forwarding

No surface test. Proposal: A counter of network calls made on the policy-resolution path (expected to stay 0), or a ShouldRateLimit span attribute; alternatively accept as untestable since ResolveEnvoyPolicy is a snapshot read by construction.

INV-7 · mutation-verified

Apply/Delete never wait on an unreachable peer longer than Behaviors.GlobalTimeout, per peer in parallel; unreachable peers are listed and the local apply succeeds.

Source blueprint Behavioral Constraints; Propagation · Resources broadcast fan-out · Defenses context.WithTimeout per peer

Purpose Policy writes stay available during partitions.

  • timeliness — an apply lasts N x GlobalTimeout with N unreachable peers, or forever without a timeout. KEEP: wall-clock bound of one GlobalTimeout plus slack; a mutex cannot satisfy it
  • liveness — local apply blocked by an unreachable peer. KEEP: ListPolicies on the applying peer

Test envoy/envoy_test.go: TestApplyIsBoundedByGlobalTimeoutAcrossUnreachablePeers: two black-hole peers, elapsed < GlobalTimeout+1s, both listed unreachable, entry stored locally and converged on live peers

Mutation (a) per-peer WithTimeout removed -> call exceeds its 3x deadline; (b) fan-out concurrency 1 -> 10s for two peers → red; reverted → green.
